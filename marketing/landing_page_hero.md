# Landing-page hero copy — multilingual

Public-facing hero block for the DFI product, positioned for the global
interview-candidate persona ("Priya"). Ready to drop into a landing page,
sales sheet, or pitch-deck cover. Translation slots filled for the
v1 launch languages.

The structural blocks (HEADLINE / SUBHEAD / VALUE / QUOTE / CTA) are
identical across every language so a single landing-page template can
swap content by locale without layout rework.

## Implementation notes for the engineer who'll wire this up

| Concern | Approach |
|---|---|
| **Auto-locale detection** | Read `navigator.language` on the landing page; serve the matching block. Fall back to English if no exact match. |
| **RTL layout for Arabic / Hebrew / Urdu** | Apply `dir="rtl"` to the language container; mirror the CTA chevrons (→ becomes ←). The hero illustration should not be horizontally flipped — keep faces oriented normally. |
| **Font fallbacks** | Use `system-ui` first, then specific fallbacks for CJK (Noto Sans CJK), Arabic (Noto Sans Arabic), Devanagari (Noto Sans Devanagari). Don't ship the fonts; rely on the OS. |
| **Quote-mark conventions** | Each language has its own typographic conventions (German „…", French «…», Japanese 「…」). The drafts above use the conventions natively. |
| **Persona name** | "Priya" is intentionally identifiable as South Asian. For locales where this might feel "othering" (e.g. an Indian-language site shouldn't have its lead persona be one specific Indian first name), consider per-locale persona variation. |

## Pre-launch quality check (do this before each language goes live)

1. **Native-speaker review pass** — paid or volunteered. Look for tone
   formality (the Hindi draft uses informal "you", Japanese uses neutral
   formal — check both are right for your buyer persona).
2. **Verify product terminology** — "behavioural friction" is our coined
   term; native translators may want to localise more aggressively or
   keep it English-loanword. Both can be right; decide per language.
3. **Test the landing page on the locale's typical device** — iPhone in
   Mumbai, Android in Lagos, iPad in Paris. The hero block must work on
   320 px wide and 1440 px wide alike.
4. **Run the page through `chrome --lang=<locale>` headlessly** and
   screenshot. Look for layout breakage from longer/shorter text.

## Final note

The non-English drafts above are **machine-assisted first passes for
native-speaker editing** — high enough quality to validate the concept
and structure, not high enough to ship as final copy without a human
native-speaker pass. Treat the file as a localisation work-order, not as
deliverable copy.
